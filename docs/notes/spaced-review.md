# Spaced review: maintainer notes

Hand-over from the agent that built it (2026-11-14). Not obvious from the code or the git history.

## Gotchas

1. **Question keys never change.** `qkey` = FNV-1a 64 of `task + "\n" + normalised prompt`, 12 hex chars (`src/lib/shared/qkey.ts`, pinned in `qkey.test.ts`). **Rewording a bank prompt orphans its scheduled rows**, and the client then retires them as "gone".
2. **Scope and dates.** Only Grade 6, and only answers with a qkey. Due dates are SAST day numbers: `floor((ms + 2h) / 86400000)`. A correct answer before the due day is ignored. A wrong answer goes to box 1, due tomorrow.
3. **Attempts are never lost.** The `review_items` update inside `/api/attempts` is in try/catch, so a scheduling failure is logged but the attempt is still stored.
4. **Generated registry.** `src/curriculum/grade6/reviewBanks.ts` is GENERATED by `scripts/gen-review-registry.mjs`. Re-run it when a Grade 6 topic with an exported bank is added; a test fails if it is stale. Every topic needs a unique task slug and an `export const bank`.
5. **Honest card count.** The client resolves questions first: on an idle callback with an 8 s timeout, otherwise no card is shown. Retiring happens only for questions missing from a *successfully* loaded bank, never on a load failure.
6. **Playability.** Whether a question can be shown is decided only by `normaliseItem` in `itemKinds.ts`. Malformed items stay scheduled but are never shown.
7. **Shells must pass the prompt.** `CapsSubjectTopic` and `PracticeRunner` post attempts with a qkey. The NST, Geo, His and Afr shells pass `current.prompt` as the 4th argument to `recordAttempt` (guarded by `shellAttempts.test.ts`). **Any new shell must do the same**, or its curated-bank answers get no qkey.

## Known limits / not verified

- Browser-tested only with NST banks. Not with Geo, His, Afr or maths banks, nor with D1-pool items; pool resolution is covered by unit tests only.
- The loader's failure and timeout paths are covered by unit tests only.
- Review sessions emit no usage events (the `track()` allowlist has no review types).
- The server's `dueCount` can exceed what is shown (caps: 200 rows, 30 candidates, 10 shown).

## Local setup

- Migrations 0001/0002 expect `item_cache` to exist already. Create a minimal pre-0002 `item_cache` first (`d1/schema.sql` already has the `section` column, so applying it and then 0002 fails).
- `next lint` does not work in this repo.
- Production migrations were applied by hand (no `d1_migrations` table): apply new ones with `wrangler d1 execute preppals --remote --file …`, before deploying code that reads them.
